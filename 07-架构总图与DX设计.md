## 关键数据流图：从用户输入到 LLM 响应

```
用户输入 "fix the bug"
    │
    ▼
main.tsx
  ├── processInput()
  │     ├── 检查是否 slash command  → /compact, /clear, /resume 等
  │     ├── 粘贴内容处理  → 存入 pasteStore，替换为 [Pasted text #1]
  │     └── 创建 UserMessage
    │
    ▼
query(params)  [query.ts:219]
  ├── startRelevantMemoryPrefetch()  ← 异步，后台运行
  └── queryLoop()
        │
        ▼
        [每轮循环]
        │
        ├── getMessagesAfterCompactBoundary()  ← 只取 compact 边界后的消息
        ├── applyToolResultBudget()             ← 大结果替换为文件路径
        ├── snipCompact()                       ← 删除历史片段
        ├── microCompact()                      ← 微压缩
        ├── contextCollapse()                   ← 折叠归档
        ├── autoCompact()                       ← 超阈值摘要
        │
        ├── buildQueryConfig()                  ← 快照 feature flags
        ├── getRuntimeMainLoopModel()           ← 选择模型
        │
        └── callModel({                         ← 调用 Claude API
              messages: prependUserContext(messagesForQuery, userContext),
              systemPrompt: fullSystemPrompt,    ← 含 CLAUDE.md + git
              tools: toolUseContext.options.tools,
              signal: abortController.signal,
            })
              │
              ▼ 流式响应
              ├── yield StreamEvent              ← UI 实时更新
              ├── 若有 tool_use block:
              │     StreamingToolExecutor.addTool() ← 立即开始执行！
              └── 若 stop_reason = end_turn:
                    ├── pendingToolUseSummary  ← Haiku 生成摘要
                    ├── handleStopHooks()      ← 检查 stop hooks
                    └── return {reason: 'completed'}
```

## 开发者体验（DX）设计分析

### 1. 流式输出的实现

Claude Code 使用 Ink（React for terminals）实现 TUI，流式更新通过 React state 驱动：

```
LLM 流式 token → yield AssistantMessage → UI state 更新 → React re-render
                                                          → Ink 计算 diff
                                                          → 终端 ANSI 输出
```

**关键技术**：
- Ink 使用 React 的虚拟 DOM 与终端的"虚拟屏幕"进行 diff，只更新变化的字符
- 流式 token 不是逐字符追加到 DOM，而是整个消息 state 更新（更高效）

### 2. 错误呈现策略

```typescript
// 不同错误的不同呈现方式
createAssistantAPIErrorMessage({ content: "...", error: 'invalid_request' })
// → 显示为红色错误框，包含可读的错误说明

// 工具失败
renderToolUseErrorMessage?()  // 工具可以自定义错误 UI
// FileEditTool: 展示"原始字符串未找到"的高亮视图
// BashTool: 展示命令输出 + 退出码
```

### 3. 斜杠命令系统

斜杠命令分两类：

**内建命令**（commands/ 目录）：
```typescript
// /commit, /review, /init, /compact, /clear, /resume 等
// 每个命令是独立文件，注册到 commands 数组
// main.tsx 中拦截，不发给 LLM
```

**用户自定义命令**（CLAUDE.md / settings.json）：
```typescript
// 用户可定义 /my-command，实际上是提示词模板
// 发给 LLM 时展开为完整提示词
```

### 4. Todo/Task 追踪系统

```typescript
// TodoWriteTool 的特殊设计
renderToolResultMessage?: undefined  // 不渲染到 transcript！

// 而是通过 AppState 更新 Todo 面板
// UI 有独立的 Todo 侧边栏，实时展示任务进度
```

这是"工具副作用驱动 UI"的典型案例：工具调用改变 state，React 自动更新 UI，不需要在 transcript 中显示。

### 5. 成本追踪

```typescript
// cost-tracker.ts + costHook.ts
// 每次 API 调用后更新:
// - input_tokens（含 cache_read/creation）
// - output_tokens
// - 估算费用（$/1M tokens × 用量）

// 在 REPL prompt 行实时显示：
// "Cost: $0.32 (↑ $0.02) | 45k tokens"
```

### 6. Bridge 架构（CLI ↔ claude.ai Web）

```
┌─────────────┐    WebSocket/SSE    ┌──────────────────┐
│  CLI 进程   │ ←──────────────────→ │  claude.ai Web   │
│  bridge/    │                     │  (浏览器)        │
└─────────────┘                     └──────────────────┘

用途:
- claude.ai 网页界面可以控制本地 CLI 执行
- 在 Web 上查看 CLI 的输出
- 远程会话（CCR: Claude Code Remote）

技术:
- replBridge.ts: REPL 端的桥接实现
- bridgeMessaging.ts: 消息格式协议
- trustedDevice.ts: 设备信任验证
- workSecret.ts: 工作区密钥
```

## 记忆与持久化系统

### 配置优先级（高到低）

```
1. policySettings     ← 企业级强制策略
2. flagSettings       ← CLI 参数 (--permission-mode 等)
3. localSettings      ← .claude/settings.local.json（不提交 git）
4. projectSettings    ← .claude/settings.json（提交 git，团队共享）
5. userSettings       ← ~/.claude/settings.json（全局用户设置）
```

### 跨会话状态

```
~/.claude/
├── settings.json           ← 用户级配置
├── projects/<hash>/        ← 项目级会话数据（hash 来自 cwd）
│   ├── history             ← REPL 输入历史（JSON Lines）
│   ├── sessions/           ← 完整会话记录（用于 /resume）
│   └── paste-store/        ← 大型粘贴内容
└── memory/                 ← Auto Memory 系统（MEMORY.md + 类型文件）

.claude/  ← 项目目录下
├── settings.json           ← 项目级配置
├── CLAUDE.md               ← 项目级指令
└── worktrees/              ← 临时 git worktrees（沙箱）
```

### Auto Memory 系统

Claude Code 有一套结构化记忆系统（本 session 自身也在使用！）：
```
类型: user / feedback / project / reference
存储: ~/.claude/memory/<type>_<topic>.md
索引: ~/.claude/memory/MEMORY.md（每行一条指针）
触发: 对话中 Claude 判断需要记住的信息
```

记忆在每次对话开始时通过 MEMORY.md 索引注入，具体文件按需读取。

## 未来演进方向（从代码特性开关推断）

源码中存在多个实验性 feature flags，暗示未来路线图：

| Feature Flag | 推断用途 |
|---|---|
| `REACTIVE_COMPACT` | 被动压缩（已逐步 rollout）|
| `CONTEXT_COLLAPSE` | 折叠归档（实验中）|
| `HISTORY_SNIP` | 历史片段删除（实验中）|
| `BG_SESSIONS` | 后台长运行 session（`claude ps` 命令）|
| `TOKEN_BUDGET` | 更精细的 token 预算控制 |
| `STREAMING_TOOL_EXECUTION` | 流式工具执行（已部分 rollout）|
| `TEMPLATES` | 任务分类模板（实验）|
| `SKILL_SEARCH` | 技能搜索（ToolSearch）|
| `CHICAGO_MCP` | Computer Use 集成 |

这些 flags 揭示了 Claude Code 的战略方向：更长的自主任务（BG_SESSIONS）、更智能的上下文管理（多种 compact 策略）、Computer Use 集成（鼠标键盘控制）。
